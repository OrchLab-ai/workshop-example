Pick your operating system

The environment check is one command, but which command depends on your machine. Answer this once and the guide remembers it.

Which Docker installation do you have?

This is the question that catches people out. Docker Desktop on Windows runs either Linux containers or Windows containers — one daemon, one mode, never both — and the workshop uses a different check for each. Don't guess. Run this and read the one word it prints:

Tells you which mode Docker is in
docker info --format '{{.OSType}}'
If that command errors, Docker Desktop is not running. Start it, wait for the whale icon to stop animating, and run it again.

macOS

Docker Desktop on macOS only runs Linux containers — there is nothing to determine.

Run these in Terminal.

1. Clone and enter the repo
git clone https://github.com/OrchLab-ai/workshop-example.git
cd workshop-example
2. Create your .env
cp .env.example .env
3. Get your token, then paste it into .env
claude setup-token
4. Run the check
./verify.sh
If port 8080 is already taken
VERIFY_PORT=8081 ./verify.sh

Windows containers · Windows

Less common, and usually deliberate — .NET Framework work needs it. You do not have to switch modes: there is a Windows-container check that proves the same five things.

Run these in PowerShell.

1. Clone and enter the repo
git clone https://github.com/OrchLab-ai/workshop-example.git
cd workshop-example
2. Create your .env
copy .env.example .env
3. Get your token, then paste it into .env
claude setup-token
4. Run the check
powershell -ExecutionPolicy Bypass -File windows\verify.ps1
If port 8080 is already taken
$env:VERIFY_PORT=8081; powershell -ExecutionPolicy Bypass -File windows\verify.ps1
The first run pulls a ~2 GB Windows base image, so give it longer than you would expect. Later runs reuse it.
If Switch to Windows containers appears to do nothing, the Containers optional feature is off. It is separate from Hyper-V. Enable it from an elevated PowerShell and reboot: Enable-WindowsOptionalFeature -Online -FeatureName Containers -All -NoRestart

Why this page exists

On Windows, "do you have Docker?" is not enough of a question. Docker Desktop runs either Linux containers or Windows containers, and it cannot do both at once. Every image the standard check uses is a Linux image, so running it in Windows-container mode fails at the build step — and it used to blame your network while doing it.

Both checks now notice when you have run the wrong one and point you at the other, so a wrong guess costs you one command. But it is faster to just ask.

Whichever pathway you take, you are looking for the same last line: ALL 5 CHECKS PASSED.
